# Contributing

## The one thing that breaks most often

This extension reads the page structure of sites nobody here controls. When
ChatGPT, Claude, Google, or Gemini change their markup, detection silently
stops. **Fixing a broken selector is the most valuable contribution you can
make**, and it's usually a small change.

Each content script has one selector constant near the top and a comment
explaining how to find its replacement:

| Site | File | What it targets |
|---|---|---|
| ChatGPT | `extension/content-scripts/chatgpt.js` | `[data-message-author-role="assistant"]` |
| Claude | `extension/content-scripts/claude.js` | `[class*="message-row"]`, minus rows containing a user-message marker |
| Gemini | `extension/content-scripts/gemini.js` | `<model-response>` custom element |
| Google AI Overview | `extension/content-scripts/google-search.js` | `.iNqyIf` (obfuscated class — the most fragile of the four) |

### Finding a new selector

On the affected page, with an AI reply on screen, open the Console:

```js
// 1. Semantic test IDs — the most stable option when available
[...new Set([...document.querySelectorAll('[data-testid]')].map(el => el.getAttribute('data-testid')))]

// 2. Custom element tags — how Gemini's markup is structured
[...new Set([...document.querySelectorAll('*')].map(el => el.tagName.toLowerCase()).filter(t => t.includes('-')))]

// 3. Last resort — right-click directly on the reply text → Inspect, and read
//    the class off the highlighted element.
```

Prefer selectors in that order. A `data-testid` or custom element tag survives
redesigns far better than a minified class name like `.iNqyIf`, which is
generated by a build step and can change on any deploy.

### Watch out for

- **Hidden duplicate content.** Google keeps an invisible "AI Overview is not
  available" block in the DOM even when a real overview renders. Filter on
  `offsetParent !== null` rather than trusting `textContent`.
- **Streaming replies.** Text arrives incrementally, so detection waits
  ~1.5s after the last mutation before recording. Don't remove that debounce.
- **Scrollback.** Re-rendering an old conversation must not re-count it.
  Dedup is by content fingerprint in `lib/aicm-report.js`; route all recording
  through `AICM.report()` rather than messaging the background worker directly.

## Running it locally

```bash
git clone https://github.com/kharthiknarayanan/ai-consumption-meter.git
```

Load `extension/` unpacked at `chrome://extensions` with Developer mode on.
There's no build step and nothing to install — it's plain JS by design, so that
anyone can read exactly what the extension does before trusting it with a view
of their AI usage.

After editing a content script: reload the extension, then hard-refresh the
target page (content scripts don't re-inject into already-open tabs).

## Testing

There's no test runner. Verification is done with small Node scripts against
the pure-logic modules (`lib/aicm-aiu.js`, `lib/aicm-insights.js`,
`lib/aicm-stats.js`, `lib/aicm-store.js`) — all of which are UMD modules that
`require()` cleanly outside the browser. If you change scoring or aggregation,
please include the script you used to check it.

Syntax-check everything before opening a PR:

```bash
for f in extension/**/*.js; do node --check "$f"; done
```

## Principles worth preserving

**No network calls by default.** The extension makes zero requests in its
default configuration. This isn't incidental — it's the core promise, and it's
what makes the privacy claim verifiable by reading the source. Any feature
needing the network must be opt-in and clearly disclosed.

**Never store content.** Only lengths are measured, never prompt or reply text.
The fingerprint is a hash used for dedup and must stay local.

**Be honest about the numbers.** aiU, man-days, and the persona score are all
estimates layered on estimates. The code comments state their assumptions
plainly, and the UI carries the caveats. Please don't remove that framing to
make the product sound more authoritative than it is — it measures consumption,
which is not the same as competence.
